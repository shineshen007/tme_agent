# 方法证据先于分析计划

新自然语言任务先检查本地输入，再提出公开方法检索词与未核验候选；可信连接器获取方法文献和官方软件来源，受限进程检查实际解释器、包版本、导出 API、签名及安装版帮助文档。只有这些阶段成功后，最终规划器才生成可审批计划。模型不能提供核验凭证。

## 使用与失败恢复

- 提供分析目标、输入、独立分析单位、数据尺度、配对/重复结构，以及任务相关的缺失值、多重检验和验证要求。缺少必要设计时先澄清，不按文件名猜测。
- 在计划预览核对方法；在 **Details** 查看查询、方法来源原文、软件版本/API、维护信息、选择理由和限制。来源及签名核验不证明科学适用性，仍需人工审查。
- 缺少所需包/API 时明确阻塞，`dependency_requirements.json` 保留官方候选发现记录和未验证限制。本功能不安装软件、不更换算法、不执行外部网页中的代码。
- 检索失败、无结果、证据过期/损坏、依赖缺失、API 不兼容和设计冲突分开记录。恢复相应条件后使用 `/retry`；已完成且有效的检索阶段可以复用。
- `/retry` 不覆盖旧 attempt。已完成统计后的文献解释仍使用既有 `/research` 流程，不把它当作方法选择的替代证据。

项目配置示例：

```yaml
planning:
  evidence:
    cache_days: 30
    offline: false
    refresh: false
    timeout: 25
    retries: 2
```

首次使用需要公开来源或已有有效缓存。离线模式不会调用在线连接器；缓存必须完整、未过期，且匹配用户要求、输入哈希、方法候选、关键配置和实际环境。切换 offline/refresh 不改变科学上下文。缓存缺失或失效时禁止新审批；显式 refresh 获取新证据，不覆盖历史版本。审批时检查时效，已审批任务执行时检查冻结完整性和环境漂移，不以重新联网更换已审批来源。

## 来源与检查边界

- 方法论文：复用 PubMed / Europe PMC，保存查询、成功/失败状态、原文段落及响应快照；引用必须指向已获取的具体来源和原文，不能只填 PMID。
- Python：PyPI 项目/版本 JSON 核验已知候选，官方登记的文档链接及安装版 API 文档提供实现依据。PyPI JSON 不是通用关键词搜索接口。
- R：CRAN / Bioconductor 官方包目录核验包与版本，获取登记页/说明和官方手册；旧 CRAN 安装版须有归档版本记录，API 文档来自实际安装版。标准 R 包使用官方手册。
- 维护状态：登记页和文档可达不等于成熟。若登记信息指向 GitHub 仓库，记录可获取的归档、禁用、更新时间及许可证信息；无法获取时明确 unknown，不用发布时间或下载量代替质量证据。
- 文件清点、格式转换及结构核验无需方法论文，但仍检查所用 API；不能把差异分析、评分、建模或绘图伪装为 utility 任务。
- 方法学引用与数据设计是否真正匹配仍需科学审查。检查器可以拒绝若干明确冲突，例如配对设计中的独立样本检验、非计数尺度使用计数模型，以及预测任务缺少验证设计；它不提供通用的语义正确性证明。
- 生成代码不得定义新的函数/类/匿名函数；已知分析命名空间的调用与审批 API 绑定，R 分析调用要求命名空间。静态检查不证明任意程序的统计语义，科学状态不会因通过检查而升级。

官方接口参考：[PyPI JSON API](https://docs.pypi.org/api/json/)、[R CRAN tools](https://stat.ethz.ch/CRAN/doc/manuals/r-release/packages/tools/refman/tools.html)、[BiocManager package discovery](https://bioconductor.github.io/BiocManager/reference/available.html)。

## 文件与协议

每次会话规划保存在 `workspace/tui/sessions/<task-id>/planning/attempt_<id>/`；无会话的直接规划调用使用 `.runtime/planning_evidence/planning/`。证据缓存位于 `.cache/planning_evidence/`，这些私有运行材料不进入公开发行包。

attempt 包括上下文哈希、候选、环境、查询和来源、依赖清单、缓存校验记录；失败另存 `failure.json`。不可变 `bundle.json` 及其绑定文件构成审批凭据，含软件和文献响应快照。

计划新增：

| 字段 | 用途 |
| --- | --- |
| `planning_protocol` | `method_evidence_v1` 协议标记 |
| `planning_evidence` | 可信快照路径、SHA256、缓存策略及命中状态 |
| `method_bindings` | 方法 ID、来源原文、适用条件、选择理由、候选取舍及限制 |
| `steps[].method_ids` | 每一步引用其已核验的方法 |
| `parameters` 中的 `planning_protocol` | 来源为 `evidence:<sha256>`；旧程序不理解该来源时拒绝执行 |

以上字段进入已有审批哈希。审批及执行均核对来源文件、用户要求、输入和环境。旧计划可读，尚未执行的旧计划必须建立新任务重新规划；已完成结果和科研续接保留。

## 验证范围

离线固定响应测试验证顺序、防伪、缓存、失败恢复、审批绑定、设计冲突和 API 约束。实际本地 R/Python 探测另在现有原生沙箱中验证。旧 UI/结果完整性测试显式替换检索与探测服务并补充合成凭据，未禁用生产哈希、引用及审批校验。

测试通过不代表真实模型、实时在线服务、Windows 原生 AppContainer 或方法的科学适用性已经验收；这些结果需分别记录。
